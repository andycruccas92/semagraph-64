# Open governance and IP posture

## Recommended public posture

Make the repository public, but do not open every future asset immediately.

Recommended split:

- software core: Apache-2.0;
- basic specification: public with attribution requirement to be finalized;
- examples: public where generic;
- advanced datasets: separate license;
- domain-specific mappings: private until strategically reviewed;
- brand name: preserve as project identity.

## Why controlled openness

The project needs public scrutiny and conceptual validation. It also needs protection from dilution, mystical misframing, and premature derivative products.

## Contribution model

Initial governance should be maintainer-led.

Accepted contribution types:

- bug fixes;
- renderer improvements;
- schema improvements;
- examples using simple concepts;
- documentation clarifications;
- tests;
- careful comparative references.

Contributions requiring review:

- new semantic mappings;
- new interpretations of states;
- references to traditional I Ching material;
- ML components;
- claims about cognition, psychology, or prediction.

## Forbidden framing

Do not merge language that frames the project as:

- divination;
- fortune telling;
- spiritual diagnosis;
- predictive psychology;
- universal symbolic truth.

## Contributor guideline

Every contribution should preserve the core thesis:

SemaGraph-64 is a compact visual-symbolic language for context and transformation, not an oracle.
