# Symbolic memory and LLM orchestration layer

## Purpose

SemaGraph-64 can operate as a symbolic context memory layer for LLM agent systems.

The LLM handles language. SemaGraph stores state.

```text
LLM = interpreter
SemaGraph = symbolic state code
Orchestrator = route selector
Memory = trajectory store
```

## Memory record

A symbolic memory record stores a context event as a compact state.

```ts
type SymbolicMemoryRecord = {
  id: string;
  source: "conversation" | "document" | "event" | "task";
  sourceRef?: string;
  stateId: string;
  tensions: string[];
  confidence: number;
  createdAt: string;
};
```

## Trajectory

A trajectory is a sequence of state records over time.

```text
S64-03 -> S64-29 -> S64-40 -> S64-46
```

The numerical IDs are not predictions. They are compact labels for context states.

## Agent routing

An orchestrator can route work according to symbolic state.

Examples:

- uncertainty + beginning -> structuring agent;
- conflict + pressure -> mediation agent;
- dispersion + repetition -> synthesis agent;
- constraint + saturation -> constraint agent;
- release + opening -> planning agent.

## Retrieval

Symbolic retrieval should combine:

1. exact state match;
2. shared lower trigram;
3. shared upper trigram;
4. Hamming distance;
5. shared tags/tensions;
6. previous transformation paths.

## MVP demo

The first demo should show:

1. input text;
2. LLM-assisted state proposal;
3. stored symbolic memory record;
4. retrieval of similar prior records;
5. agent routing decision;
6. final response generated by the LLM.

## Safety

The layer must not be used to claim psychological diagnosis or prediction. It stores interpretive state labels for software orchestration.
